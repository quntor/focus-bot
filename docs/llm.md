# Интеграция модели

## Граница решения

Текстовая модель участвует в пяти смысловых касаниях:

1. связывает свободный текст намерения с одной из активных задач и определяет,
   является ли намерение шагом или большой задачей;
2. разбирает короткий отчёт: был ли прогресс и виден ли следующий шаг;
3. по смыслу любой формулировки отличает обычное намерение, список задач,
   немедленный старт, завершение одной задачи, завершение с переходом,
   завершение задачи вместе с рабочим днём и отдельный конец дня;
4. во время активной сессии различает отвлечение, застревание, досрочное
   завершение и вопрос, возвращая только короткий ответ и безопасное действие;
5. по кнопке «Разобрать» предлагает шаги задачи, опираясь на ответ человека,
   как он сам видит задачу; возвращает только список строк или, если задача
   размыта, один уточняющий вопрос (не больше одного на разбор); задачи из
   списка создаёт код.

Voice сначала переводится в текст отдельной Audio-to-Text моделью, после чего
проходит тот же третий контур. Аудио не сохраняется на диск или в БД.

Таймеры, уведомления, исход сессии, очки, серия и любые записи, влияющие на
геймификацию, определяет код. Модель не получает инструментов или прямого
доступа к базе.

## Выбранный вариант

`src/llm/openai-compatible.ts` вызывает стандартный `chat/completions` через
встроенный `fetch`. Это сохраняет текущий `LlmProvider`, не добавляет SDK и
позволяет менять OpenAI-compatible провайдера конфигурацией.

Для API моделей Сбер 500:

```env
LLM_BASE_URL=https://shared1.multitool.works:4000/v1
LLM_MODEL=gpt-5.4-mini
# Опционально: включает голосовые сообщения. Использует тот же API key/base URL.
STT_MODEL=whisper-large-v3
LLM_API_KEY=<SBER_API_TOKEN>
```

На 27.09.2026 `/models` возвращает обе выбранные модели. `gpt-5.4-mini` выбран
после сравнения шести кандидатов и шаблонного fallback на обезличенных русских
сообщениях; результаты и ограничения зафиксированы в
[session-help.md](session-help.md). Синтетическая русская речь также дошла до
`whisper-large-v3`. Перед сменой модели в production всё равно нужен живой
smoke-тест обычного и голосового сообщения из Telegram.

Текстовая модель включается только полным набором трёх `LLM_*`. Если не задана ни одна,
бот работает как раньше. Неполный набор останавливает старт приложения, чтобы
ошибка конфигурации не выглядела как успешно включённая модель.
`STT_MODEL` опциональна и отдельно включает платное распознавание голоса.

## Ошибки и безопасность

- каждый вызов ограничен таймаутом конкретного касания;
- сетевой сбой, таймаут, не-2xx, не-JSON или ответ не по строгой продуктовой
  схеме переводят касание на детерминированный fallback;
- тело ошибки внешнего API не попадает в исключение или лог;
- ключ передаётся только в `Authorization: Bearer` на настроенный HTTPS URL;
- пользовательский текст не логируется; аналитика получает только
  `llm_used` и категорию fallback;
- первый классификатор не получает список задач; второй узкий проход сопоставляет название
  только с задачами текущего пользователя под метками `t1..tN`, а не по внутренним id.
- каждый реальный вызов пишется в журнал `component_calls` (касание, статус,
  машинный код ошибки, задержка, токены) — это зачётные обращения конкурса,
  см. [metrics.md](metrics.md);
- не больше 300 вызовов модели и распознавания на человека за скользящие сутки
  (`LLM_CALLS_PER_DAY` в `src/analytics/calls.ts`, счёт — по `component_calls`).
  Активному человеку нужно 60–100. Сверх лимита вызов не делается и в журнал не
  попадает: касание уходит на тот же путь, что и при выключенной модели
  (`llm_fallback` с `reason=budget`), голос просит писать текстом, раз в сутки
  пишется `llm_budget_exceeded`. Без лимита один аккаунт со скриптом сжёг бы
  общую квоту ключа, а его «обращения» выглядели бы накруткой.

## Проверка, выкладка и откат

До включения нужны: unit-тест адаптера, полный suite, успешный короткий запрос к
реальному API и smoke-тест касаний. После включения контролируются события
`intent_parsed`, `report_parsed`, `tasks_parsed`, `session_help_requested`, `task_breakdown_done`, `voice_transcribed` и
`llm_fallback`.

Откат не требует миграции: удалить три `LLM_*` из `.env.production` и пересоздать
контейнер приложения. Бот сразу возвращается к детерминированному режиму.
Голос отключается независимо удалением одного `STT_MODEL`.
