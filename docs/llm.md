# Интеграция модели

## Граница решения

Текстовая модель участвует в трёх смысловых касаниях:

1. связывает свободный текст намерения с одной из активных задач и определяет,
   является ли намерение шагом или большой задачей;
2. разбирает короткий отчёт: был ли прогресс и виден ли следующий шаг.
3. отличает намерение одной сессии от списка задач и разбирает явное
   «эту закончил, приступаю к следующей».

Voice сначала переводится в текст отдельной Audio-to-Text моделью, после чего
проходит тот же третий контур. Аудио не сохраняется на диск или в БД.

Таймеры, уведомления, исход сессии, очки, серия и любые записи, влияющие на
геймификацию, определяет код. Модель не получает инструментов или прямого
доступа к базе.

## Выбранный вариант

`src/llm/openai-compatible.ts` вызывает стандартный `chat/completions` через
встроенный `fetch`. Это сохраняет текущий `LlmProvider`, не добавляет SDK и
позволяет менять OpenAI-compatible провайдера конфигурацией.

Для Cloud.ru:

```env
LLM_BASE_URL=https://foundation-models.api.cloud.ru/v1
LLM_MODEL=ai-sage/GigaChat3-10B-A1.8B
# Опционально: включает голосовые сообщения. Использует тот же API key/base URL.
STT_MODEL=openai/whisper-large-v3
LLM_API_KEY=<Key Secret>
```

Текстовая модель включается только полным набором трёх `LLM_*`. Если не задана ни одна,
бот работает как раньше. Неполный набор останавливает старт приложения, чтобы
ошибка конфигурации не выглядела как успешно включённая модель.
`STT_MODEL` опциональна и отдельно включает платное распознавание голоса.

## Ошибки и безопасность

- каждый вызов ограничен таймаутом конкретного касания;
- сетевой сбой, таймаут, не-2xx, не-JSON или ответ не по строгой продуктовой
  схеме переводят касание на детерминированный fallback;
- тело ошибки внешнего API не попадает в исключение или лог;
- ключ передаётся только в `Authorization: Bearer` на настроенный HTTPS URL;
- пользовательский текст не логируется; аналитика получает только
  `llm_used` и категорию fallback;
- задачи передаются под метками `t1..tN`, а не внутренними id, и только для
  текущего пользователя.

## Проверка, выкладка и откат

До включения нужны: unit-тест адаптера, полный suite, успешный короткий запрос к
реальному API и smoke-тест касаний. После включения контролируются события
`intent_parsed`, `report_parsed`, `tasks_parsed`, `voice_transcribed` и
`llm_fallback`.

Откат не требует миграции: удалить три `LLM_*` из `.env.production` и пересоздать
контейнер приложения. Бот сразу возвращается к детерминированному режиму.
Голос отключается независимо удалением одного `STT_MODEL`.
