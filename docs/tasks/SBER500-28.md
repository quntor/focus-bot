# SBER500-28 — номер в списке задач

## Цель и доказательство

После списка активных задач Антон ответил `2`; бот спросил об отчёте или новой
задаче. Причина: номера списка не имели детерминированного обработчика и попадали
в семантический маршрутизатор. Новый DB-backed regression на исходном коде упал:
карточка второй задачи не открывалась, вместо неё — fallback парсера.

## Решение и состояние

Ветка `workspace/anton`, worktree `anton--focus-bot--workspace-anton`.
Локально, без push/deploy. Чужие изменения `docs/tasks/SBER500-26.md` сохраняются.

- Перед LLM текст/расшифрованный голос из цифр проверяет последний показанный
  нумерованный список. Номер выполняет тот же action, что соответствующая кнопка.
- Снимок содержит только ID/номера/режим/страницу, не названия. Это bot-event,
  не пользовательское обращение; `pendingInput` и незавершённый отчёт не меняются.
- После рестарта или изменения порядка сохраняется показанный ID; удалённая
  задача не подменяется следующей. Новые ответы/уведомления гасят старый список.
- Проверяется отпечаток pendingInput/активного таймера; TTL — 6 часов.
- Проверяется соответствие подписи кнопки строке списка (включая сокращённые
  длинные подписи): кнопка «Начать с первого» под списком шагов не превращается
  в выбор последнего номера. Этот review-regression сначала упал, затем прошёл.
- Карточка действий не переключает задачу автоматически; запуск из карточки
  сохраняет исходный дедлайн. В прямом picker номер сразу запускает задачу.
- Старые списки до релиза не имеют сохранённого снимка: открыть «Мои задачи» заново.

## Ключевые файлы и проверка

`src/bot/task-number-prompt.ts`, `tasks.ts`, `context.ts`, `texts.ts`,
`src/tg/webhook.ts`, outgoing worker/reminder paths, analytics event schema,
`src/bot/task-number.test.ts`.

Node24, отдельная disposable DB `focus_test_sber28`, fake Telegram/STT/LLM.
Начальный regression: 1 failed. Focused до review: 3 файла / 20 тестов
(14 сценариев выбора номера + 6 analytics), без failed/skipped. Review дополнительно
воспроизвёл подмену номера кнопкой «Начать с первого»: 1 failed, после исправления
15/15 целевых passed. Добавлен 16-й сценарий сокращённой длинной подписи.
Первый общий прогон шёл параллельно с последней правкой префикса и не является
финальным свидетельством; следующий прерван перед исправлением review-дефекта.
Финальный полный DB-backed прогон на окончательном коде:
57 файлов / 548 тестов passed, без failed/skipped (включая все 16 новых сценариев).
DB `focus_test_sber28_final`; Node24 typecheck/build, Prisma validate и diff-check passed.
Скан новых файлов на bot/API token patterns: совпадений нет.

## Что сделано ботом

Детерминированный выбор номера перед LLM, durable snapshot показанного списка,
та же семантика кнопки/текста/цифровой расшифровки, защита от подмены и устаревших
вопросов. Готово локально к review в `workspace/anton`, без push/deploy.
Полный набор 548/548, типы, сборка, схема и diff проверены. Live Telegram UX
не проверялся; миграций/новых зависимостей нет. Код-коммит указан в Plane.

## Что проверить

После отдельно разрешённого релиза: «Начать сессию» с несколькими задачами → `2`
открывает действия второй задачи без вопроса об отчёте. Нажать «Начать»:
задача привязана, дедлайн таймера прежний. «Мои задачи» → вторая страница → `8`
открывает задачу под показанным номером. Число в ответ на вопрос о длительности
по-прежнему меняет длительность, не выбирает задачу. Production не проверен.
