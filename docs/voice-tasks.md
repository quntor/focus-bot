# Голосовой и текстовый список задач

## Проблема

Сейчас свободный текст воспринимается только как намерение одной сессии, а
голосовые сообщения webhook игнорирует. Пользователь не может одной фразой
зафиксировать несколько дел на день, выбрать одно из списка или сказать:
«эту задачу сделал, приступаю к следующей».

## Решение MVP

Один общий контур обрабатывает и текст, и расшифрованный голос:

1. Telegram voice скачивается в память с жёсткими лимитами и передаётся во
   модель `whisper-large-v3` через API моделей Сбер 500 с явным `language=ru`
   и коротким словарём продуктовых терминов (`Милавица`, `VDS`, `FocusBot`),
   чтобы модель не переводила русскую речь в английский и реже искажала названия.
2. Аудио не пишется на диск и не сохраняется в БД. Пользователь видит
   полученную расшифровку.
3. Первый смысловой проход получает только текст и флаг, есть ли текущая задача.
   Названия задач из базы ему не передаются: это не даёт модели копировать непроизнесённые
   задачи или пропускать новые. Если нужен старт или переход, второй узкий проход сопоставляет
   выделенное название с личным списком под метками `t1..t20`.
4. Строгий JSON-ответ выбирает одно из семи намерений по смыслу фразы, а не по словарю команд:
   - обычное намерение одной сессии;
   - добавить от одной до десяти задач;
   - сразу начать существующую или новую задачу;
   - отметить одну существующую задачу готовой;
   - отметить текущую задачу готовой и без паузы начать следующую;
   - одновременно отметить существующую задачу готовой и закончить рабочий день;
   - закончить рабочий день и показать итог.
   Для списка каждое явно названное самостоятельное действие сохраняется ровно
   один раз; близкие переформулировки одного действия объединяются в более
   конкретное название, а разные действия над одним объектом не склеиваются.
5. Код проверяет схему, переводит временные метки в ID и сам выполняет записи.
   Модель не получает ID из БД и не может вызвать действие напрямую.
   Если первый ответ нарушил JSON-схему, parser делает ровно одну повторную
   попытку с усиленным требованием типов в пределах общего 8-секундного бюджета;
   ошибки API и timeout не повторяются.
   После валидации код консервативно объединяет только названия с тем же
   действием и почти одинаковым объектом. Пользователю показывается весь
   распознанный список, включая повторно названные активные задачи; при записи
   точное совпадение переиспользует существующую задачу и не создаёт дубль.

После добавления бот показывает активные задачи inline-кнопками. Нажатие задачи
открывает отдельные действия, а `Начать` запускает обычную сессию с действующим
правилом длительности. Явная фраза
«сделал X и приступаю к Y» завершает текущую running-сессию как `done`, отмечает
X выполненной и без отдыха запускает Y. Для paused-сессии автоматическое
переключение не выполняется: сначала нужно вернуться к работе.

Фраза вроде «больше не хочу работать» завершает день: текущий таймер
закрывается как незаконченная работа, сама задача остаётся активной, а в итоге
показывается суммарное рабочее время по каждой задаче. Паузы в это время не входят.
Если в той же фразе пользователь явно сообщает о выполненной задаче, бот сначала
находит её только среди личных активных задач и отмечает готовой, а затем закрывает
день. Неизвестная задача не создаётся, и день не закрывается частично.

## Библиотека задач и старт сессии

Постоянная кнопка `Мои задачи` и команда `/tasks` показывают все активные задачи
страницами по шесть. Каждая задача занимает отдельную строку; нажатие открывает
карточку с действиями `Начать`, `Удалить` и возвратом на ту же страницу списка.
Удаление мягкое: статус меняется на `dropped`, история связанных сессий остаётся,
а в ответе есть кнопка возврата. Задачу текущей running-, paused- или
collecting-сессии убрать нельзя.

`Начать сессию` сохраняет быстрый старт: таймер запускается сразу с предыдущей
задачей или без задачи. Следом бот показывает активный список. Выбор задачи
меняет `taskId` и формулировку внутри уже идущей сессии, но не меняет
`startedAt`, `plannedEndAt` и длительность. Если пользователь сначала открыл
`Мои задачи`, когда активной сессии нет, выбор задачи создаёт и запускает новую
сессию с обычным правилом длительности; первый автоинтервал без истории — 40
минут.

Выбран inline-список с пагинацией: он не засоряет постоянную клавиатуру
названиями, которые быстро устаревают, и не создаёт по сообщению на каждую
задачу. Reply-клавиатура содержит только устойчивые действия сессии и
`Мои задачи`. Новая таблица и миграция не нужны — используются `Task.status` и
существующая связь `FocusSession.taskId`.

В первом утреннем вопросе активные задачи показываются тем же постраничным
списком, но выбор работает быстрее: нажатие сразу запускает выбранную задачу и
таймер, без промежуточной карточки действий. Если дневная цель ещё не задана,
список появляется сразу после её выбора. При пустом списке остаётся обычный
вопрос `С чего начнёшь?`, на который можно ответить текстом.

## Почему так

### Выбрано: Whisper → текст → GigaChat → строгие действия кода

- один и тот же смысловой парсер для голоса и текста;
- можно показать и проверить расшифровку;
- аудио и продуктовую логику легко тестировать отдельно;
- Whisper доступен по тому же API моделей Сбер 500 и тому же командному токену;
- ошибки STT не превращаются незаметно в операции с задачами.

### Не выбрано: мультимодальная модель сразу превращает аудио в действия

Сложнее отделить ошибку распознавания от ошибки разбора, выше стоимость,
доступные модели внешние, а тесты и fallback хуже.

### Не выбрано: локальный Whisper на VDS

Текущий VDS — 1 vCPU / 2 ГБ RAM. Локальное распознавание добавляет тяжёлую
модель, задержки и операционную нагрузку ради объёма, который на MVP дешевле
обработать по API.

## Границы и безопасность

- только личные чаты и пользователь с принятым согласием;
- voice: не больше 180 секунд и 5 МБ; Telegram Bot API дополнительно ограничивает
  скачивание 20 МБ;
- не больше пяти платных распознаваний на пользователя в час; шестое блокируется
  до скачивания файла и вызова STT;
- до десяти задач за сообщение, название до 80 символов;
- все чтения и записи фильтруются по `userId` из проверенного Telegram `from.id`;
- callback содержит только указатель; владение задачей повторно проверяется в БД;
- выдуманная или чужая метка второго прохода не превращается в ID;
  владение задачей повторно проверяет код;
- при сбое STT аудио не передаётся в текстовый парсер, пользователю предлагается
  повторить или прислать текст;
- в событиях сохраняются длительность, длина и число задач, но не аудио и не
  полный текст расшифровки.

## Совместимость и конфигурация

- любой обычный текст или voice проходит смысловую классификацию; жёсткого словаря команд нет;
- STT включается только при заданном `STT_MODEL`; используется тот же
  `LLM_BASE_URL` и `LLM_API_KEY`;
- без STT текстовые задачи работают, voice получает понятный отказ;
- новая миграция не требуется: существующей модели `Task` достаточно.

## Приёмка

1. «Сегодня хочу сделать A, B и C» создаёт три активные задачи и показывает их
   кнопками выбора.
2. «Просто добавь задачу A» создаёт одну задачу; повтор снова показывает A для
   выбора, но не создаёт точный дубль.
3. Voice проходит `getFile` → download → Whisper → тот же разбор; аудио не
   сохраняется.
4. Нажатие задачи открывает её карточку; `Начать` запускает сессию именно с ней,
   `Удалить` мягко скрывает её, чужой task ID не работает.
5. «Эту сделал, приступаю к B» при running-сессии корректно закрывает текущую,
   отмечает её задачу `done` и запускает B.
6. Слишком длинный voice, выключенный STT, timeout и невалидный JSON дают
   безопасный ответ без частичных записей.
7. Существующие текстовые сценарии, таймеры, outbox и одна активная сессия не
   регрессируют.
8. Реальная проблемная фраза сохраняет «поправить все косяки», объединяет два
   варианта «планирования дня» и предпочитает написание `Милавица`, `VDS`,
   `FocusBot` без хранения пользовательской расшифровки в prompt.
9. `Начать сессию` сразу запускает таймер и показывает активные задачи; выбор
   задачи не обнуляет и не сдвигает таймер.
10. `Мои задачи` и `/tasks` листают весь активный список по одной задаче в строке;
    мягкое удаление можно отменить, чужую и текущую задачу изменить нельзя.
11. Произвольная фраза о старте находит существующую задачу или создаёт новую, затем сразу запускает таймер.
12. Произвольная фраза о конце дня закрывает таймер, не отмечает задачу готовой и показывает время по задачам.
13. Составная фраза «закончил на сегодня, задачу X сделал» отмечает существующую X готовой и затем закрывает день.

## Выкатка и откат

Сначала код и миграционно нейтральные тесты, затем `STT_MODEL` в production env и
один ручной voice-smoke на командном аккаунте. Откат — убрать `STT_MODEL`:
текстовый контур останется рабочим, voice отключится без изменения данных.
