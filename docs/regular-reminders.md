# Регулярные напоминания

Утверждены Антоном 2026-10-05, SBER500-26. Контракт: [спецификация](specs/regular-reminders.md).


### Утренний возврат — уточнение Антона10.10.2026, SBER500-41

Если ответ приходит только в следующих рабочих сутках, считаем, что человек ушёл спать: истёкшая timed running-сессия policy1 сохраняется до текущего plannedEndAt, а не до утреннего ответа. Рабочие сутки уже начинаются в04:00 по timezone пользователя; полночь сама по себе не обрывает работу. Сравнивается срок, не старт: явно продлённый сегодняшний интервал не обрезается. Подтверждённые предыдущие периоды и привязки задач сохраняются, паузы не считаются.

Утренний рабочий старт (включая /start), продолжение той же задачи и актуальная кнопка продолжения создают новый таймер. Старая работа закрывается без автоматически придуманного результата, завершения задачи и очков; старая цепочка отменяется. Явный исход может подтвердить результат прошлой работы, но не засчитывает ночь; отчёт доступен от момента подтверждения. Таймерless/free и уже paused не меняются этим правилом. Установка тишины остаётся независимой.

Статус только читает: показывает суммарное время к учёту до планового конца, не898минут, но не закрывает сессию. Молчание, feedback и ошибка LLM не являются новым стартом. Интерпретация всех текстовых реплик остаётся за LLM. Восстановление старой работы фиксируется под owner lock и snapshot/input fence; если затем пришёл новый ввод, старое сохранение остаётся, а отменённый ввод не должен создавать лишний таймер.

## Пользователь

Обновление SBER500-41 по запросу Антона 09.10.2026: утренний вопрос — максимум
один раз за местный день, без приветствия, только если неизвестны планы и не было
фактической работы. Автоматическое приглашение не создаёт подготовительную сессию.
Быстрый старт отвечает одним подтверждением и сразу запускает таймер; старый
ритуал, next_step и необязательный список задач не присылаются следом.

Утром ответ «Сегодня работаю» открывает обычный выбор занятия, но не запускает
работу. «Сегодня выходной» отменяет утренний вопрос только на календарную дату;
ручной старт разрешён. «Продолжить» запускает полный интервал в той же сессии,
«Пора отдыхать» ставит её на паузу. «Ещё отдыхаю» сбрасывает только расписание
вопросов. Вернувшись, продолжаете ту же сессию с новым полным интервалом.
После завершения и явно выбранного отдыха кнопка возврата открывает новый старт.

«Перерыв» без текущей работы сохраняет отдельный отдых без таймера, не выходной
и не фиктивную сессию. Он переживает перезапуск и смену дня: автоматические
приглашения отменяются до успешного нового старта. Статус, помощь и просмотр
задач не снимают отдых. Назначенная самим человеком встреча остаётся.
Сводка/приглашение не перебивают незаконченный вопрос. Оба механизма проверяют
свежие данные перед отправкой; кеш с приветствием заменяется контекстным fallback.

На перерыве «Уже отдыхаю» позволяет указать 5/10/15 или своё число минут **до
исходного нажатия перерыва**. Уточнение ограничено последним непрерывным рабочим
периодом, пересчитывает смены задач; повтор не вычитает время снова. Напоминания
не являются границами учёта. Неизвестное занятие остаётся временем без задачи.
Распределение времени из явного отчёта приоритетнее автоматических привязок.

Тишина в напоминаниях и настройках не меняет постоянные переключатели и не
останавливает сессию. «Сегодня больше не беспокоить» закрывает её на фактическом
действии без результата, отчёта и очков. «Возобновить напоминания» снимает тишину
и ждёт полный интервал. Постоянные проверки управляют work/break, «писать первым»
— morning/post_rest и сводками. Окно morningTime–eveningTime не пересекает полночь.
Явный ночной старт/возврат разрешает только текущую фазу до ближайшего утра;
старые дневные циклы ночью спят. Нет залпа накопленных сообщений.

## Включение и данные

Аддитивные миграции `20261005090000_reminder_chains`,
`20261005093000_llm_budget_reservations` и `20261005094500_legacy_work_residual`;
`20261009103500_idle_rest_context` добавляет nullable users.idle_rest_at;
история/очки не переписываются. При явном возврате из legacy паузы восстановимые
границы сохраняются; недостающая история остаётся доказуемым временем без задачи,
а не выдуманными рабочими периодами.
`REMINDERS_ENABLED=false` по умолчанию, `REMINDER_USER_IDS` — явный comma-separated
canary список Telegram ID. При следующем взаимодействии участник получает
user-policy1; текущая legacy работа остаётся policy0, новая/явный resume — policy1.
Env задаётся в действующем `APP_ENV_FILE` compose.prod.yml; examples содержат флаг off.
Не включать/не выкатывать без команды администратора.
Список `REMINDER_USER_IDS` управляет первоначальным enrollment. Удаление ID
не отключает уже переведённого policy1 пользователя; для аварийной остановки
canary использовать глобальный `REMINDERS_ENABLED=false` и recreate app.

ReminderChain revision/ordinal обеспечивает один слот. Owner lock и send gate
охватывают проверку состояния, но не внешний LLM/Telegram запрос. После генерации
контекст проверяется снова. Текст/fingerprint/provenance сохраняются в outbox,
удаляются каскадом с пользователем, не входят в экспорт событий. 429 повторяет
тот же текст/слот, uncertain не пересылается, следующее время — от сохранённого
начала попытки. Crash генерации использует fallback без повторного платного вызова.
Дневной общий лимит300 резервируется атомарно; crash оставляет консервативную
резервацию до истечения скользящих суток. Резервации, как обезличенный журнал
вызовов, не содержат Telegram ID/текстов.

## Совместимый откат

Оставить аддитивную схему и **этот совместимый build**, выставить
`REMINDERS_ENABLED=false`. Sweeper отменяет pending новых цепочек, ручные действия
и физический учёт сохраняются; policy1 защищена от legacy autoFinish. Не откатывать
на старый binary без guard. После повторного включения reconcile материализует
новую revision отменённого слота, сохраняет фазу и coalesce до одного вопроса.
Не запускать destructive down migration на пользовательских данных.

## Проверка перед выпуском

Node24, локальный отдельный PostgreSQL, без Telegram/платных API:

```bash
PYTHON=python3 TEST_DATABASE_URL=<isolated-test-db> npm test
npm run typecheck
npm run build
```

Перед активацией человек оценивает реальные LLM golden-контексты (нет плана,
вчерашний план, завершённая задача, выходной, молчание), нейтральность и фактическую
привязку текста; затем canary Telegram work/break/quiet/stop/retro/429/restart.
Локальные mocks не заменяют эту оценку. Живые вызовы и отправки требуют отдельной
авторизации. [Карточка проверки](tasks/SBER500-26.md).
