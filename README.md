# Фокус — напарник по рабочим сессиям

Telegram-бот, который сидит рядом, пока ты работаешь. Спрашивает, с чего начнёшь,
проверяется в середине сессии и разбирает отчёт в конце. Помнит, что было вчера.

Начать труднее, чем сделать: человек знает, что нужно делать, и не садится, потому
что никто не ждёт результата. Таймер и трекер фиксируют провал, но не спрашивают,
над чем ты работаешь, и не помогают вернуться после срыва. Живой напарник это
решает, но требует расписания, языка, подписки и камеры.

**Статус: бот работает в Telegram, идёт набор первых пользователей (октябрь
2026).** План по неделям — в [docs/roadmap.md](docs/roadmap.md).

## Регулярные напоминания (SBER500-26, выключены по умолчанию)

Для явного canary предусмотрены `REMINDERS_ENABLED=true` и список Telegram ID
в `REMINDER_USER_IDS`. Новый режим применяется к новым интервальным сессиям
и явному возврату с перерыва; существующие legacy и свободные сессии не переносятся.
Утро спрашивает «работаю/выходной» не более одного раза за местный день,
только если ещё нет плана или фактической работы; сессия сама не создаётся. Работа повторяет
полный интервал, отдых — 10/30/60/120 минут после первого планового напоминания.
«Перерыв» без текущей работы сохраняет отдых без таймера до успешного нового
старта; автоматических приглашений в этом режиме нет. Молчание не завершает работу/перерыв. «Отключить уведомления» сохраняет режим,
«Сегодня больше не беспокоить» завершает без результата и очков; тишина — до
местной полуночи. [Руководство, проверка и откат](docs/regular-reminders.md).

## Цикл сессии (legacy)

1. Постоянная кнопка «Начать сессию» сразу запускает таймер без обязательной
   задачи; длительность подбирается по истории (для новичка — 40 минут). Уже
   после старта работу и длительность текущего рабочего периода можно изменить
   отдельными кнопками; отвечать необязательно. Свободный текст и `/focus` сохраняют подробный поток
   с намерением и предложением длины.
2. Идёт рабочий период. В середине — короткий пинг «на месте?»; его можно
   отключить в `/settings`, в том числе для уже идущей сессии. Первая задача,
   названная после простого старта, получает время от начала текущего рабочего
   периода; дальнейшая смена закрывает её интервал и открывает следующий, не
   сбрасывая и не продлевая общий таймер. Закрытая посреди периода задача
   перестаёт копить время; сессию закрытие задачи не заканчивает никогда.
3. Постоянная кнопка «Перерыв» завершает текущий рабочий период. Вернувшись,
   человек запускает новый полный период настроенной длительности в той же
   логической сессии либо начинает новую сессию. Время отдыха в работу не входит.
   Когда отдых по длине сессии кончается, бот зовёт обратно; перерыв, забытый на
   3 часа, закрывает сессию и засчитывает работу до него.
4. Финиш — исход кнопкой: сделал / не сделал / вышло другое. Потом пара слов,
   можно пропустить. В отчёте можно постфактум распределить фактическое время:
   «15 минут на презентацию, 5 на письма, остальное на отчёт». Такое уточнение
   меняет только разбивку по задачам, но не длительность, очки или серию.
   «Готово, иду отдыхать» закрывает текущую задачу и сессию сразу, а «не
   закончил, пойду отдыхать» — обычный перерыв.
5. После отчёта бот спрашивает про отдых: отдохнуть, сразу дальше, вернуться
   позже, на сегодня всё. Текстовый или голосовой отчёт с явной встречей
   («завтра в 8:30») одновременно сохраняет результат, закрывает день и ставит
   эту встречу — отдельный вопрос про отдых уже не нужен.
6. Вечером — сводка дня с подтверждением. «Всё, на сегодня» заканчивается итогом и
   вопросом о следующей встрече, а не тишиной; идущую сессию оно закрывает без
   исхода, время — до планового конца. Сутки продукта идут до 4:00: «завтра»,
   сказанное в час ночи, — это утро после сна. Время можно назвать обычным текстом
   или голосом, например «начну сегодня в 11»; это назначает встречу, а не запускает
   задачу немедленно.

Автомат сессии — `src/session/fsm.ts`, тексты для пользователя — `src/bot/texts.ts`.

## Что делает модель, а что намеренно нет

Модель: принимает свободный текст и голос, различает команды по списку задач,
связывает намерение с существующими задачами, разбирает отчёт и коротко помогает
при отвлечении или застревании во время активной сессии. Аудио сначала
преобразуется в текст отдельной моделью распознавания. Модель не выполняет
действия: код показывает человеку только безопасную кнопку подтверждения. На
человека — не больше 300 вызовов модели за сутки; сверх этого бот работает на
шаблонах, как без модели ([docs/llm.md](docs/llm.md)).

Без модели: таймер, расписание пингов, текст самого пинга, начисление очков,
серия, учёт событий и метрики. Причины две. Экономика — у вовлечённого
пользователя больше тридцати касаний в день, и каждое лишнее обращение к модели
умножается на размер аудитории. Проверяемость — метрики и начисления должны быть
воспроизводимыми, а не результатом решения модели.

## Стек

TypeScript, Node 24, Telegram Bot API через вебхук. PostgreSQL, Prisma. Отложенные
пинги и сводки — очередь в таблице с ключом идемпотентности, а не таймеры в
процессе: перезапуск приложения не должен терять сообщения. Аналитика своя, в той
же базе. Тесты — vitest. Контейнер и CI на GitHub Actions.

## Локальный запуск

Нужны Node 24+ и PostgreSQL (в docker-compose он уже есть).

```bash
npm ci
cp .env.example .env   # заполнить токен бота, секреты вебхука и строку подключения
docker compose up -d db
npx prisma migrate deploy
npm run dev
```

Тесты с базой запускаются при заданном `TEST_DATABASE_URL` (отдельная база — тесты
стирают таблицы). В CI база поднимается сервисом, и пропуск этих тестов там —
ошибка. Метрики — `npm run metrics -- --segment all|active|roles|sessions`;
зачёт конкурса — `--segment zachet`, пометка команды — `npm run team`, выгрузка
для организаторов — `npm run export` (подробно в [docs/metrics.md](docs/metrics.md)).

Публичное руководство для новых пользователей доступно на `GET /guide`; две
инфографики лежат в `public/guide` и отдаются только по явному списку путей.
Вебхук слушает `POST /tg/<TELEGRAM_WEBHOOK_PATH>` и принимает только запросы с
заголовком `X-Telegram-Bot-Api-Secret-Token`, равным `TELEGRAM_WEBHOOK_SECRET`;
проверка живости — `GET /healthz`. Для локальной разработки адрес пробрасывается
любым туннелем и регистрируется через `setWebhook` с `secret_token`.

## Структура

```
src/http        HTTP-сервер вебхука: секрет, лимиты, таймауты
src/tg          разбор апдейтов, маршрутизация, дедупликация, Telegram API
src/bot         потоки: сессия, день, аккаунт; тексты; callback_data
src/session     автомат сессии, длительность, техники
src/retention   правила учёта, очки, серия
src/outbox      очередь отложенных сообщений и воркер
src/jobs        сборщик: брошенные сессии, роли, чистка
src/llm         адаптер модели и строгие схемы ответа
src/stt         распознавание voice через OpenAI-compatible audio/transcriptions
src/analytics   журнал событий: типы, схемы payload, роли
src/social      приглашения (только схема и функции, без интерфейса)
src/scripts     дашборд метрик, регистрация вебхука
prisma          модель данных и миграции
docs            схема событий и метрики, развёртывание, план по неделям
```

## SBER500-39: единый LLM-вход

Every text (including slash commands, reply-keyboard labels, onboarding answers, numbers and transcribed voice) goes through one bounded LLM routing call. Strict typed payloads are checked against the current owner's state. Feedback, uncertainty and provider/schema/timeout/budget failures do not change session/task/pending/timers. Callback buttons remain explicit user actions. The deprecated `SEMANTIC_ROUTER_ENABLED` input cannot enable legacy parsing; disabling the LLM makes text fail closed, while callbacks remain usable. No migrations required.

Rollback requires restoring the previous verified code release, not flipping a parser flag; preserve the database and credentials. This change does not authorize release/deployment.
